## Goal（一句话）

用「qwen-eye 看片段逆推 prompt → h3 fl2va 首尾帧复现 → 与原片段比对打分」的闭环，把
prompts.json 从「看起来合理」升级为「**经复现验证的可信真值**」，产出
(首帧, 尾帧, prompt) 高价值数据集 —— rejection sampling 造 SFT 真值。

## 动机（现状缺口）

- 现有 prompt 反推只看每镜首/中/尾 ≤3 张**静帧**（`analysis/local_vision_facets.py`），
  action/camera facet 靠静帧脑补 —— README 已警告「action 写简了下游视频模型会瞎演/违反物理」。
  **看片段本身**（帧序列）是 action/camera 质量的正解，独立于闭环就有价值。
- prompt 没有任何验证机制：写得好不好无从度量。round-trip 是唯一客观信号。

## 四个关键设计决策（决定数据集是否「真有价值」）

1. **首尾帧对比无意义。** fl2va 被首尾帧 condition，重生成片段首尾帧必然像。
   **有效信号全在中段**：中间帧 embedding 轨迹 vs 原片段、动作链一致性。打分器围绕 mid-frame 设计。
2. **verdict 必须归因。** prompt 好 ≠ h3 做得到。VLM judge 看原片段 vs 重生成并排，
   区分「prompt 描述了 X 模型渲染了 Y」（prompt 好/h3 不行）vs「prompt 欠约束」（prompt 烂）。
   不归因 → 数据集系统性偏向简单动作。
3. **rejected 保留。** 带归因的 rejected = hard negatives + h3 能力边界测绘。verdict 带 reason。
4. **成本决定架构。** ~100 镜/集 × 5-8min = **8-13h/轮** h3 渲染 + 须先杀 TTS 服务器腾显存。
   → per-shot cache（mirror WR-04 4-tuple）+ 断点续跑 + 先抽样 N 镜验证评分器 + 验证专用可降分辨率。

## Phase 划分（接续 v1.2 Phase 17 → 18-22，全 additive）

- **Phase 18: Contract v1.3** — `roundtrip.schema.json`（per-shot: regen video ref +
  scores{midframe_clip, vlm_judge} + verdict{accepted/rejected} + attribution + reason）+
  `asset.json#data` optional 挂载 + fixture + validate gate（mirror v1.2 三层门）
- **Phase 19: qwen-eye v2 看片段** — 每镜抽 8 帧序列逐帧 `observe_single` 问动作/运镜 →
  文本合并升级 **action/camera facet**；同时把 audio_semantic 当 ear 输入融进 prompt。
  务实版零新基建；正解版（vLLM + Qwen3-VL-8B 视频原生）留作 v2 升级
- **Phase 20: h3 regen 客户端** — kst 直连 ComfyUI API 提交 fl2va workflow（参考 kmc
  batch_render 模式），per-shot cache + VRAM guard（自动 `/free` + 剩余显存检查 + TTS 共存检测）
- **Phase 21: Scorer** — 便宜信号先行（中段帧 CLIP/SigLIP 轨迹相似度）；VLM judge 归因
  （可用全局 glm-structured-output skill 做 schema 化输出）
- **Phase 22: 审阅 HTML + 数据集导出** — gallery 加 round-trip 面板（原片段 vs 重生成并排 +
  分数 + accept 按钮）；accepted 子集导出独立 dataset 目录（首帧/尾帧/prompt.json/manifest）。
  canvas consumer defer

## Scope 边界（不做）

- 不改分镜检测/转录/分离基线（v1.0 约束延续）
- 不训练任何模型（纯数据生产；SFT 消费是下游别的事）
