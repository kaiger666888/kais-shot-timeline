## Phase 11 schemas (the export target + dropdown filter source)

### spec/schemas/speaker-edits.schema.json (73 lines — the Export-edits target)
Top-level object (additionalProperties:false). Fields the HTML export MAY set:
  - merge_groups: array of arrays of spk_id (≥2 items each) — operator merges similar speakers
  - splits: object {spk_id: [{label, member_indexes}]} — operator splits a speaker into N (PARTITION of turns)
  - confirm_ids: array of spk_id → review_state='confirmed' (Plan 01 link_speakers.py reads)
  - reject_ids: array of spk_id → review_state='rejected' (soft-delete; ID reserved)
  - link_mappings: object {spk_id: char_id} — SPEAKER-01 spk→char N:M map (orthogonal to confirm_ids)
  - review_notes: string (audit; ignored by link_speakers)
All fields optional — empty {} schema-valid. PatternProperties enforce ^spk_[0-9]{3}$ keys + ^char_[0-9]{3}$ link_mappings values.

### spec/schemas/characters.schema.json — the dropdown source
Top-level list of entries; filter to entry.get("review_state") == "confirmed" for the dropdown (Pitfall 7 upstream — do not let operator link a speaker to an unconfirmed character). Each confirmed entry contributes {id (char_NNN), name (string)} to the dropdown options.

## Export-edits JS shape (the contract the HTML must produce)

```javascript
const edits = {
  merge_groups: state.mergeGroups.filter(g => g && g.length >= 2),
  splits: Object.keys(state.splits).reduce((acc, k) => { acc[k] = state.splits[k]; return acc; }, {}),
  confirm_ids: Array.from(state.confirmIds).sort(),
  reject_ids: Array.from(state.rejectIds).sort(),
  link_mappings: {...state.linkMappings},  // spk_id → char_id (omits 旁白/群杂 null links)
  review_notes: `Exported from HITL speaker review HTML on ${new Date().toISOString()}`,
};
```
