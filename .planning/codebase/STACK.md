## Platform Requirements

**Development:**
- Python 3.10+
- `ffmpeg` and `ffprobe` on `$PATH` (with `libx264` + `libdav1d` builds — Ubuntu/Debian default ffmpeg ships both)
- NVIDIA GPU + matching CUDA toolkit strongly recommended (Demucs `htdemucs` and Whisper `large-v3` on CPU are extremely slow)
- Multi-GB model downloads on first run: Whisper `large-v3` (~3 GB), Demucs `htdemucs` (~80 MB) — cached under `~/.cache/huggingface` / `~/.cache/torch`
- Sufficient disk for intermediates: each video produces a transcode (optional), per-frame JPGs, 4 PCM WAV stems, and base64-encoded frames JSON (single episodes can exceed 100 MB of intermediates)

**Production:**
- No deployment target. This is a one-shot local analysis tool; outputs (HTML + JSON) are intended to be hand-inspected or copied into downstream platforms (kais-movie-center / kais-movie-pipeline / kais-aigc-platform). No packaging, no Dockerfile, no CI

## Notable Architecture Choices

- **No package manifest.** `README.md:160-164` lists `pip install scenedetect demucs faster-whisper pillow numpy opencv-python` as the install command. There is no lockfile, so reproducing the exact environment shown above requires running that command on a clean Python 3.12 + CUDA 12.4 box.
- **Demucs is shelled out, not imported.** `audio/separate_stems.py:55-65` runs `python -m demucs --name htdemucs -o <dir> <input>` as a subprocess. This is intentional (Demucs' CLI handles model download + GPU dispatch), but it means Demucs cannot be hot-loaded in-process.
- **Whisper is imported lazily and tries both backends.** `audio/transcribe.py:109-123` — `--backend auto` attempts `faster_whisper.WhisperModel` first, falls back to `openai_whisper.load_model` on `ImportError` or runtime failure.
- **All video I/O goes through ffmpeg/ffprobe.** No moviepy, no av, no PyAV. Frame extraction (`html/gen_shots_preview.py:24-39`, `html/gen_timeline_html.py:972-987`) uses `ffmpeg -ss <ts> -i <video> -frames:v 1 -q:v 2 -vf scale=480:-1`.
- **Generated HTML is monolithic and self-contained.** Python f-string templates embed all CSS, all JS, all frame thumbnails (as base64), and the full shots/audio/transcript payload as JSON literals inside a `<script>` tag. The only external resources the HTML references are the source `.mp4` and the three `<basename>_{vocals,drums,other}.wav` stem files (expected co-located with the HTML).
