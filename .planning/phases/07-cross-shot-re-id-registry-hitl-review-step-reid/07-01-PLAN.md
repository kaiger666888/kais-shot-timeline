Top-level properties (ALL optional — no `required` field; empty {} is schema-valid for the no-edits case):
- `merge_groups`: array of arrays of cluster_id strings (min 2 per group) — clusters to merge into one
- `splits`: object mapping cluster_id → array of new label strings (min 2 labels) — split one cluster into N
- `renames`: object mapping cluster_id → display name string (min 1 char) — rename without changing ID
- `type_overrides`: object mapping cluster_id → "char"|"prop" — correct wrong type prefix
- `confirm_ids`: array of cluster_id strings — mark confirmed (→ canonical)
- `reject_ids`: array of cluster_id strings — mark rejected (soft-delete, ID preserved)
- `review_notes`: optional free-text string (audit only; apply_edits ignores)

All cluster_id values MUST match `^(char|prop)_[0-9]{3}$` (same pattern as registry.schema.json + characters/props schemas).

apply_edits.py applies in FIXED ORDER: merge → split → rename → type_override → confirm/reject. This order + the deterministic ID allocation (splits use max_existing_N + 1) guarantees idempotency — same edits.json applied twice produces byte-identical canonical files (Pitfall 5 prevention).
