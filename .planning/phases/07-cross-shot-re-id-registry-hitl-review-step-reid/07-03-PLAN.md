Step-by-step apply logic (RESEARCH Pattern 3 lines 447-513):
1. Load draft (registry.draft.json) → `clusters = {c["cluster_id"]: dict(c) for c in registry["clusters"]}`.
2. Validate edits against registry-edits.schema.json (Draft202012Validator pre-apply — never trust unvalidated operator input).
3. **merge_groups**: for each group, canonical_id = group[0]; merge all members into canonical; soft-retire non-canonical IDs (pop from clusters, but they stay in the draft file for reference integrity). Recompute mean_cosine as average of merged clusters' mean_cosine.
4. **splits**: for each source cluster_id, allocate new IDs via `max_existing_N + 1` (deterministic — sort existing IDs by numeric suffix, take max, +1). Source ID preserved as first split; new IDs for subsequent splits. Members are NOT reassigned (split is a labeling operation — operator decides member assignment in the HTML; apply_edits just creates the new ID entries as copies of the source, reviewer assigns members via the HTML). SIMPLIFICATION: splits create N new confirmed entries from the source cluster's data (name derived from split labels); the source cluster is soft-retired. This keeps the apply logic deterministic without requiring member-assignment in the edits shape.
5. **renames**: for each cluster_id → new name, store in a `renames` dict applied at build-entry time (name is a display field, not an ID change).
6. **type_overrides**: for each cluster_id → new type ("char"|"prop"), change the cluster_id prefix (char_ ↔ prop_). This changes which canonical file the entry flows to. The ID number stays the same; only the prefix changes.
7. **confirm_ids**: mark each cluster `review_state = "confirmed"`.
8. **reject_ids**: mark each cluster `review_state = "rejected"` (soft-delete — preserved in draft for reference, never flows downstream).
9. **HARD GATE (Pitfall 7)**: build canonical entries — for each cluster in clusters: if `review_state != "confirmed"` → SKIP (hard gate, not filter). Route to characters (char_ prefix) or props (prop_ prefix) based on final cluster_id prefix.
10. **_build_char_entry / _build_prop_entry**: construct canonical entry with `id` (cluster_id), `name` (from renames or default like "未命名角色_<N>"), `representative_image` (canonical path `characters/<id>.png` or `props/<id>.png`), `appearance_shots` (sorted unique shot_ids from cluster members), `review_state` ("confirmed" — hard-coded, NOT copied from draft). looks[]/states[] are NOT populated (Phase 7 scope — future look-editor tooling).
11. **ffmpeg representative PNG**: for each canonical entry, pick best member (highest mask_quality; quality_rank = {"high":0, "medium":1, "low":2, "unusable":3}; default first member if no signal). Resolve frame_pos → timestamp via _resolve_frame_ts (shot start/end + position). ffmpeg extract → `<subdir>/<id>.png`.
12. **Schema validation pre-write**: Draft202012Validator against characters.schema.json + props.schema.json. Fails loud.
13. **Atomic write**: temp + os.replace for both files.
