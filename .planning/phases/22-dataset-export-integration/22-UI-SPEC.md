## Design System

| Property | Value |
|----------|-------|
| Tool | none —— 本 phase UI 面是 Python 生成的 **monolithic offline HTML**（vanilla JS，无框架、无构建、零新依赖）。非 React/Next/Vite，shadcn gate 不适用 |
| Preset | not applicable |
| Component library | none —— 手写 CSS 组件，唯一模板 = `html/gen_registry_review.py` + `html/gen_speaker_review.py`（card / queue sidebar / sticky header / sticky export bar 四件套直接复用） |

**生成器形态契约**（mirror 先例，非视觉但 checker 相关）：

- 单文件 self-contained：CSS/JS/data 全 inline；**外部资源仅 2 个 `<video>` src**（原视频 + regen mp4，相对路径，经 `scripts/serve.py` Range 服务）——这是与 registry review（base64 缩略图全 inline）的唯一形态差异，由 PRESENT-01「双 video 同步播放」决策强制

## Spacing Scale

Declared values (must be multiples of 4) —— 先例是**高密度数据审阅面板**，用密档刻度（4/8/12/16/20/24），不用模板默认的稀疏 8 点刻度：

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | 按钮内水平 padding、badge 内边、列表项间距、视频行 gap |
| sm | 8px | 卡片内元素纵向间距、按钮 gap、card-header gap、queue 项内边 |
| md | 12px | card-body padding、sidebar padding、header 上下 padding |
| lg | 16px | cards-container padding、卡片 grid gap、summary pill gap |
| xl | 20px | sticky header / export bar 左右 padding |
| 2xl | 24px | （保留；本面板无页面级大留白——密档审阅面板） |

Exceptions（非 spacing 的 stroke/radius，先例原值保留）：`1px` hairline border（#30363d）；queue 项 `3px` 左侧 verdict 色条；sim bar 高 `4px`、圆角 `2px`；卡片圆角 `8px`；pill 圆角 `12px`。

## Typography

统一为 4 档字号（先例的 12px 并入 13px、10px 并入 11px；700 并入 600 —— 排版细节 discretion 内的轻度归一，降低契约分叉）：

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Display（header h1 面板标题） | 18px | 600 | 1.2 |
| Heading（export bar 按钮 + per-card 三态覆盖按钮 / sidebar h2） | 14px（h2 用 13px 视作 Body 档） | 600 | 1.2 |
| Body（summary pill / 卡片正文 / queue 与次级控件标签 / score 行） | 13px | 400 | 1.5 |

> 字号归属消歧（ui-checker FLAG 收口）：**14/600** 只给「产生 edit 动作或导出」的按钮（export bar + per-card 三态）；**13/400** 给其余一切可点元素（queue 跳转、sync 控件、折叠开关）。两档并存是对 gen_registry_review.py 的 byte-fidelity 而非疏漏——executor 勿归一。
| Meta（queue 项 / reason 正文 / members 式列表 / badge / mono 数值） | 11px | 400（mono id 600） | 1.5 |

- 所有 shot_id / 分数 / hash / 时窗 / model 名 / τ 值一律 `monospace`
- 中文 UI（CLAUDE.md lock，先例一致）；按钮标签沿用先例中英混合风格（`✓ Accept` / `✗ Reject`），三态第三个用中文 `⟲ 维持 auto`

│ queue     │  cards-container（单列，max-width 1200px，padding 16） │

│ shot_NNN  │  │   + `sim=0.9731 · clip-vit-l14`（mono 11px）      │  │

- 与 registry review 的差异仅一处：**卡片区单列**（`grid-template-columns: 1fr; max-width: 1200px`）而非 `minmax(440px,1fr)` 自动多列——双 16:9 视频并排需要整行宽度；其余（sticky header 80px 高、`scroll-padding-top: 80px`、smooth scroll、queue 项 `#card-shot_NNN` 锚点）逐字 mirror
- 双 video 行：左 = 原片段 `<video src="{video_rel}#t={start:.3f},{end:.3f}" controls preload="metadata">`（Media Fragments 时窗裁切）；右 = regen `<video src="{regen.path}" controls preload="metadata">`；各上方 11px 灰标签 `原始片段 (t=12.3-15.6s)` / `重生成 (regen)`；`object-fit: contain`，well 背景 `#0d1117`
- 每个 video 上方角落放 mono 时长 chip（`⏱ 3.3s` 原窗时长 / regen `duration_sec`）——双片时长不对齐是常态（17k+5 帧对齐），操作员需一眼看到

## Interaction Contract

### 1. 双 video 同步播放（PRESENT-01 锁定概念，交互细节收口）

- **主控按钮**（accent 色，video 行下方）：`▶ 同步播放` ⇄ `⏸ 同步暂停` 单按钮切换，同时驱动两个 video `play()`/`pause()`
- `⏮ 重置`：左 video `currentTime=start_sec`、右 video `currentTime=0`，再暂停
- **同步是事件级，不是时间轴从属**：不做 `timeupdate` 逐帧跟主（双片时长/帧率天然不齐，强锁会抖动且与原生 controls 打架）。原生 controls 保留，允许操作员独立拖拽细看——这是审阅工具不是播放器
- 一侧先 `ended` 不联动另一侧（操作员自行重置）
- video 加载失败（regen 文件被移动/serve 未起）：JS `error` 事件把该 well 替换为灰底占位块（`#30363d` 背景 + States 节文案），**不出 broken 图标、不阻塞另一侧与全卡操作**

### 2. 三态覆盖按钮（HITL 语义 mirror registry Confirm/Reject + 新增第三态）

- 每卡三按钮：`✓ Accept`（active 绿 `#238636`）/ `✗ Reject`（active 红 `#da3633`）/ `⟲ 维持 auto`（active 蓝 `#1f6feb`）
- **默认态 = 三按钮全不 active**（维持 auto 是隐式默认，未点击 = 未复核）
- 互斥：任一时刻至多一个 active。点 Accept 清 Reject；点「维持 auto」清 Accept/Reject 并显式标记该卡已复核（不产 edit 记录）
- 卡片状态类：`state-accept`（绿边 + 1px glow）mirror `state-confirmed`；`state-reject`（红边 + **opacity 0.45**）mirror `state-rejected`；维持/未动 = 无状态类
- 无 auto verdict 的卡（未裁决）三按钮照样可用——human 覆盖是这类卡拿到 verdict 的唯一路径

### 3. 复核进度 affordance（CONTEXT「已复核计数」落地）

- `已复核 R/N`：R = 点过**任一**三态按钮的卡数（含显式「维持 auto」）；N = 有卡总数
- queue 侧同步：已复核卡对应 queue 项加 `✓` 前缀或降不透明度 0.6（二选一，executor 取 `✓` 前缀）
- export bar 左侧实时显示 `已复核 R/N · 覆盖 A/R`（A=显式 accept 数，R=显式 reject 数）；R<N 时 export 按钮仍可点（registry 先例不硬门面板侧，confirmed-only 硬门在 apply CLI），但 `⏳ 已复核 R/N` pill 在 R<N 时保持黄色 `#d29922`，R=N 变绿

### 4. Queue 排序（mirror「最难决定先审」）

`sort key = (verdict/scores 缺失 ? 0 : 1, |midframe_sim − τ| 升序, shot_id 升序)`——信息不全的最先，其余按 τ 边界距离升序（边界镜最需要人眼），同距按 id。queue 项：verdict 色条（绿/红/灰）+ `shot_NNN` + 微型 sim bar + `{sim:.3f}`。

### 5. Export edits 流（confirmed-only apply 闭环）

- Sticky 底栏 `📥 Export edits (roundtrip-edits.json)` → Blob + `URL.createObjectURL` 下载（逐行 mirror `exportEdits()` 先例）
- **导出 payload 契约**（mirror registry-edits 的 confirm_ids/reject_ids 风格；schema 文件本 phase 落 `spec/schemas/roundtrip-edits.schema.json`）：

```json
{
  "accept_overrides": [7, 12],
  "reject_overrides": [3],
  "review_notes": "Exported from roundtrip review HTML on <ISO-8601>"
}
```

  shot_id 升序；**只收显式 Accept/Reject**（「维持 auto」不进 edits）；**与 auto 判定同向的显式覆盖照导**（例：auto-accepted 再显式 Accept → 进 accept_overrides，apply 后 source 变 human，防未来重打分翻案——这正是 schema `source` 字段的设计用途）
- 面板永不写 sidecar（HITL 硬门）。apply CLI（mirror `registry/apply_edits.py`：schema 预校验 + confirmed-only + idempotent）由操作员显式运行，写回 `verdict{decision, source:"human", decided_at}`，逐行审计打印 `[roundtrip-apply] shot_007 auto→human/accepted`，收尾打印计数汇总

### 6. Prompt 快照折叠

- 原生 `<details><summary>▸ Prompt 快照 (prompt v{prompt_version})</summary>`，**默认折叠**
- 展开区（11px mono 为主）：`prompt_text` 全文 + facets 表（`subject/action/camera/scene/lighting/style` 六键，label 灰 + 值正文色）+ `character_refs` / `prop_refs`（mono 逗号列表，空则 `(无)`）
- 全部字符串过 `_esc`（prompts 含 route/模型产出文本）

## XSS Hardening Presentation Rules（PRESENT-01 明文扩展，SC3 测试集挂钩）

1. **`_esc()` 5 字符转义（`& < > " '`，`&` 先）应用于进入 HTML text/attribute 的每一个动态字符串**。本面板强制清单：`judge.reason`、`attribution`（enum 也转，defense-in-depth）、`verdict.decision/source`、`status.error`、`midframe_sim.model`、`engine_name/engine_version/prompt_version`、`prompt_text` 与全部 facets、`character_refs/prop_refs`、`asset_name`、shot 时窗数字先 `str()` 兜底（mirror `_esc` docstring 惯例）
2. **JSON-in-`<script>` bootstrap**：`json.dumps(payload, ensure_ascii=False).replace("</", "<\\/")` 防 `</script>` 破出（registry/speaker 双先例原样）
3. **JS 侧动态更新（badge/按钮态/计数）一律 `textContent`，禁止 `innerHTML` 拼接模型文本**——三态切换只改 class 与固定文案
4. onclick 内插值仅限 pattern-locked 的 shot_id（整数），先例同款 defense-in-depth 仍过 `_esc`
5. SC3 明文验证用例（进 plan 测试集）：`<script>` / `onerror=` / base64 三类 payload 注入 fixture 的 `reason` 与 `attribution` 邻位字段 → 断言渲染后 HTML 中 payload 以转义态出现且无 `<script>` 执行 / 无 onerror 属性存活
6. 长度上界已由 schema 预 bound（reason/error `maxLength: 2000`，T-18-02）——呈现层不截断，CSS `word-break: break-word` 防长串撑破卡片
